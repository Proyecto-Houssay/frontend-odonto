# Flujo de trabajo y planificación

## Git

- develop es la rama de integración acordada por Sprint 0.
- Mantener ramas de trabajo por integrante; integrar mediante Pull Request hacia develop.
- Asociar cada PR con sus HU/TR y milestone de sprint.
- Evitar subir secretos, archivos .env locales y datos personales reales.

## Sprints y backlog

El Product Backlog establece dependencias; los milestones representan Sprint 0–6. La fecha y responsables se deciden con el equipo al planificar la capacidad. Cerrar una HU requiere verificar todos sus criterios y tareas vinculadas.

## Revisión funcional

Antes de cerrar un issue, comprobar el flujo completo en frontend y API: autenticación/rol, solicitud, respuesta, errores, estados vacíos y regresión relevante.
